# Optional Protobuf C++ runtimes

```bash
TYPE=osx ARCH=arm64 NO_COLOR=1 UI_ANIM=0 ./apo update protobuf
# Linux: TYPE=linux ARCH=64 GCC_VERSION=10 ...
# Also has toolchain paths for iOS/tvOS/visionOS/Catalyst/watchOS,
# Android, Emscripten, Visual Studio and MSYS2.
```

This formula is opt-in. It does not add Protobuf to the core library list,
register automatic platform builds, or replace ANGLE's vendored dependencies.
The dedicated smoke workflow checks native Linux GCC10 and macOS; other target
toolchains need native CI validation before automatic publication is enabled.

Source release **36.2** identifies its C++ runtime as **7.36.2**. Both source
archives have pinned SHA-256 values: Protobuf plus its required Abseil
**20250512.1**. `utf8_range` is included in the Protobuf archive. CMake uses
only these local sources, without finding a host Abseil installation or
fetching dependencies during configuration.

The build installs static `libprotobuf` and `libprotobuf-lite`, Abseil and
UTF-8 support archives, headers, upstream CMake targets and pkg-config files.
Zlib compression support, tests, examples, UPB and compiler tools are disabled.
Visual Studio builds include Release and Debug with the engine's selected CRT.
Emscripten inherits the engine's thread flags and selects memory32/memory64.

The complete upstream SDK layout is retained under
`out/protobuf/lib/<type>/<platform>/`, including its `include/` and `lib/`
directories. Headers are also copied to the usual `out/protobuf/include/`.
Each runtime archive has Pkl metadata with the source hash and Abseil pin.
Use the upstream CMake targets to resolve the support libraries automatically:

```cmake
list(PREPEND CMAKE_PREFIX_PATH "/path/to/out/protobuf/lib/osx/MAC_ARM64")
find_package(protobuf CONFIG REQUIRED)
target_link_libraries(my_app PRIVATE protobuf::libprotobuf)
# For messages generated with optimize_for = LITE_RUNTIME, choose
# protobuf::libprotobuf-lite instead. Do not link both runtimes together.
```

Generate `.pb.cc`/`.pb.h` with **host protoc 36.2**, then compile them for the
target. The runtime formula does not build or execute a target `protoc` during
cross-compilation. Official matching host compilers are available in the
[upstream release](https://github.com/protocolbuffers/protobuf/releases/tag/v36.2).
C++ generated code and runtime versions must match; see the
[upstream compatibility policy](https://protobuf.dev/support/cross-version-runtime-guarantee/#cpp-and-rust-specific-guarantees).

For Apple platforms keep these full/lite SDKs separate. The generic `apo modular`
archive combiner is not suitable for combining both alternative runtimes and
all support archives into one XCFramework.

## ANGLE relationship

Apothecary's pinned Google ANGLE revision lists its own Protobuf checkout in
[DEPS](https://github.com/google/angle/blob/7e8009eb2c42996fe6e7337bf8d12e1cfe4a1b80/DEPS#L1153).
The ANGLE GN files at that revision do not directly declare a Protobuf dependency
for the `libEGL`/`libGLESv2` build. A separate Apothecary build will not replace
that checkout or change ANGLE's GN dependency graph.

## Validation

`bash scripts/tests/test-protobuf.sh` downloads and verifies sources, builds
through this formula, copies the SDK and runs the engine's config-export hook.
It moves the package before linking separate full/lite consumers with messages
generated by a hash-verified host `protoc` 36.2. The tests check serialization,
UTF-8 strings, 64-bit values and reflection in the full runtime. The workflow
runs this on Linux GCC10 and macOS. `PROTOBUF_SOURCE_DIR` can reuse a previously
verified source directory for a local rerun.
