# VS2019 compiler test

`build-vs2019-64` builds both existing Windows core bundles for x64 with the
VS2019 v142 / MSVC 14.29 compiler installed on `windows-2022`. VS2022 provides
the CMake generator and MSBuild host; `VS_VER=17` describes that host, while
`VS_TOOLSET=v142` selects the compiler, headers and libraries.
The profile pins Windows SDK 10.0.19041.0, installed on `windows-2022`, using
`VS_WINDOWS_SDK_VERSION` for both compiler activation and formula configuration.

`CPP_STANDARD=max` resolves to CMake's `CXX_STANDARD=23`, which MSVC 19.29 maps
to `/std:c++latest`. This enables the maximum features implemented by that
compiler. It does not imply complete C++23 support. Explicit numeric standards
remain supported. The compiler probe checks `_MSC_VER`, `_MSVC_LANG` and the
CMake platform toolset, then builds and runs a C++ consumer using concepts and
`std::span`.
After packaging, a second consumer links and runs against the extracted archive:
zlib compression/decompression for bundle 1 and fmt formatting for bundle 2.

Apothecary selects the 14.29 compiler path, passes the same toolset to CMake and
MSBuild, and retains it when recipes request the VS environment again. Missing
v142 tools cause an error instead of falling back to a newer compiler.

The workflow runs for relevant PRs and can be dispatched manually after merging.
It uploads separate `vs_2019` core review archives and failure logs. These are
experimental builds: release publication and verification against current
openFrameworks master remain separate work. A successful library build does not
prove that current openFrameworks, which requests C++23, supports VS2019.
